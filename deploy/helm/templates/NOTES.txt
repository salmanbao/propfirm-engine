## Verify the deployment

```bash
# Wait for pods to be ready:
kubectl -n {{ .Release.Namespace }} wait --for=condition=ready pod -l app.kubernetes.io/instance={{ .Release.Name }} --timeout=120s

# Hit the health endpoint:
kubectl -n {{ .Release.Namespace }} port-forward svc/{{ .Release.Name }}-server 8080:{{ .Values.server.service.port }}
curl http://localhost:8080/health  # → ok
curl http://localhost:8080/ready   # → ready
curl http://localhost:8080/metrics  # → Prometheus format

# Tail the server logs:
kubectl -n {{ .Release.Namespace }} logs -f -l app.kubernetes.io/component=server

# Tail the worker logs:
kubectl -n {{ .Release.Namespace }} logs -f -l app.kubernetes.io/component=worker
```

## Notes

- The engine is **unauthenticated** (internal-only). The NetworkPolicy
  restricts ingress to the namespaces listed in
  `networkPolicy.ingressFromNamespaces`. Update that list before
  deploying to production.

- The idempotency backend is `{{ .Values.idempotency.backend }}`.
  For high-QPS production, use `redis` (recommended) or `postgres`.
  Avoid `memory` in production — it loses dedup state on every deploy.

- Migrations are run automatically on first server startup when
  `postgres.runMigrations` is true (the default). To disable:
  `helm upgrade {{ .Release.Name }} . --set postgres.runMigrations=false`.

- OTLP exporter is configured but only active when the binary is
  built with the `otel` cargo feature AND
  `observability.otlp.endpoint` is non-empty. Point it at your
  OpenTelemetry Collector (e.g. `http://otel-collector.observability:4317`).

For more details: https://github.com/salmanbao/propfirm-engine/tree/main/docs
